# Backendテスト方針と結果

## 方針

件数だけを増やすのではなく、学校内データの漏えい・権限外操作・不正ファイル保存につながる処理を優先します。Service層はRepositoryまたはSQLをモックし、PostgreSQLやS3を起動しなくても業務ルールを再現できるようにしています。

## 重点テスト

| 対象 | 検証内容 | 防ぎたい問題 |
| --- | --- | --- |
| セッションCookie | 本番で`Secure`・`SameSite=None`を設定 | クロスサイト環境での認証失敗 |
| 無効・削除アカウント | 発行済みCookieを持っていても全APIで拒否 | 無効化後の継続利用 |
| 管理者保護 | 自己変更・自己削除と最後の管理者削除を拒否 | 管理不能状態への移行 |
| 非公開相談 | 無関係な利用者にはNot Foundとして扱う | 質問の存在・内容の漏えい |
| 質問回答 | 担当外の教員による回答を拒否 | 権限外操作 |
| 学校連絡 | 対象所属、作成者・管理者の確認権限 | 誤配信・既読情報の漏えい |
| 添付形式 | ファイル名でなく実データからMIME判定 | 偽装ファイルの保存 |
| 添付制限 | 最大5件、1件10MB、合計25MB | 容量の濫用 |
| 添付整合性 | DB登録失敗時に保存済みオブジェクトを削除 | S3の孤立データ |
| 添付閲覧 | 権限確認前にS3を読まない | 非公開ファイルの漏えい |

## 実行方法

```bash
go test ./... -race -covermode=atomic -coverprofile=coverage.out
go tool cover -func=coverage.out
go vet ./...
```

## アプリ内通知（2026-09-28）

`TEST_DATABASE_URL` にテスト用PostgreSQLの接続先を指定すると、通知の統合テストも実行します。
テスト専用スキーマを作成・削除し、全マイグレーションの適用・再実行を検証します。
CIではPostgreSQLサービスを使用します。未指定時は統合テストのみスキップします。

- 通常編集で通知なし、通知ONで対象者だけに配信、所属重複の排除
- 作成者・操作ユーザー・無効／削除ユーザーの除外
- 再通知、既読化の冪等性、他人の通知操作拒否
- 更新後の配信対象、所属変更・期限切れ時の閲覧制限
- 通知INSERT失敗時の投稿更新ロールバック、投稿削除時の通知削除
- 認証付き通知APIの成功・エラー応答

ローカル検証: PostgreSQL 18、`go test ./... -race -covermode=atomic` と `go vet ./...` 成功。
全体カバレッジ18.1%（既存CI下限10%以上）。

## Compose初期化の修正（2026-09-28）

SQLディレクトリをPostgreSQLの`/docker-entrypoint-initdb.d`へマウントすると、
初期化で024まで適用された後、APIの履歴管理が001から再実行し、
008が新しい通知テーブルの`comment_id`不在で失敗します。
ComposeのSQLマウントを削除し、API起動時の`database.Migrate`に一本化しました。

今回のローカルDBは初期化ログで001〜024の成功を確認し、バックアップ後に
欠けた適用履歴を補完して復旧しました。一般の既存DBで確認せず適用履歴を補完しないでください。
ヘルスチェック200、localhost:5173からのCORS応答、未認証/api/meの401、
フロントHTTP 200を確認しました。

## 再投稿・履歴仕様への変更

通知ONの編集は元の投稿をUPDATEせず、新しい投稿を作成する仕様へ変更しました。
025でprevious_post_id（自己参照、分岐禁止、削除制限）とchange_summaryを追加しています。
- 通常編集は最新投稿を更新。重要変更は変更概要必須で再投稿・通知。
- 元の本文・配信対象・既読記録を保持。新しい投稿は未読から開始。
- タイムライン、作成した連絡、検索は最新版のみ。詳細から前の投稿と最新版へ移動。
- 過去の投稿は編集不可。履歴に紐づく投稿は削除不可。
- 各投稿の元の閲覧権限と期限を維持。閲覧できない過去／最新投稿のリンクは表示しない。
- 添付は元の投稿に保持し、新しい投稿への自動コピーはしない。必要な添付は再アップロード。
- 元投稿を行ロックし、同時再投稿の分岐を防止。通知失敗時は新規投稿もロールバック。

実DBで履歴・本文保全、既読分離、通知宛先、複数回再投稿、過去編集拒否、閲覧権限、
最新版タイムライン、ロールバックを検証。Go全テスト（raceあり）とvet成功。
フロント24テスト、coverage実行、build、lint成功。
