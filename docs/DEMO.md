# デモデータと確認手順

このデータは学校内情報・コミュニケーション基盤の一連の利用フローを確認するための、開発・デモ専用データです。本番の通常起動では投入されません。

## 投入方法

PostgreSQLを起動し、バックエンドリポジトリで明示的にseedを実行します。

```bash
docker compose up -d postgres
docker compose run --rm -e DEMO_SEED=true backend go run ./cmd/seed
```

ホスト上のGoから実行する場合：

```bash
DEMO_SEED=true \
DATABASE_URL='postgres://twitter:twitter_password@localhost:5432/twitter?sslmode=disable' \
go run ./cmd/seed
```

- `DEMO_SEED=true`がない場合は実行を拒否します。
- `APP_ENV=production`の場合も実行を拒否します。
- APIサーバーの通常起動や`docker compose up`だけではseedされません。
- 同じコマンドを再実行すると、デモ用レコードを更新して指定状態へ戻します。ユーザー、所属、連絡、質問が実行回数分増えることはありません。
- seed終了前に、所属配信、private相談の閲覧範囲、確認集計、横断検索を自動検証します。検証に失敗した場合は非0で終了します。

## 学校連絡と状態

| タイトル | 投稿者 | 対象 | 優先度 |
| --- | --- | --- | --- |
| 来週の数学小テストについて | 田中先生 | 2年A組 | 通常 |
| 進路希望調査の提出について | 佐藤先生 | 2年 | 重要 |
| 土曜日の練習時間変更 | 鈴木先生 | サッカー部 | 重要 |
| 奨学金説明会のお知らせ | 佐藤先生 | 2年 | 通常 |

「奨学金説明会のお知らせ」は、「奨学金」検索でお知らせ・公開Q&A・担当窓口の3種類を確認するための補助データです。

意図的に設定する既読・確認状態：

- 進路希望調査：山田太郎は閲覧・確認済み、佐々木花子は閲覧済み・未確認
- サッカー部練習：山田太郎は閲覧・確認済み、高橋健は未読
- サッカー部連絡は山田太郎と高橋健に表示され、佐々木花子には表示されません。

現在の集計仕様は対象所属の全メンバーを数えるため、サッカー部所属の投稿者・鈴木先生も対象人数に含まれます。そのためサッカー部連絡の初期集計は「対象3、閲覧1、確認1、未確認2」です。進路希望調査は「対象2、閲覧2、確認1、未確認1」です。

## 質問・相談

| 質問 | 質問者 | 公開範囲 | 初期状態 | 回答者 |
| --- | --- | --- | --- | --- |
| 小テストに二次関数は含まれますか？ | 山田太郎 | public | answered | 田中先生 |
| 奨学金について相談したい | 佐々木花子 | private | open | デモ操作で佐藤先生が回答可能 |
| 学校端末からWi-Fiに接続できません | 高橋健 | public | resolved | 鈴木先生 |
| 奨学金の募集時期を知りたい | 山田太郎 | public | answered | 佐藤先生 |

「奨学金の募集時期を知りたい」は、private相談を漏らさず「奨学金」検索に公開Q&Aを出すための補助データです。

private相談「奨学金について相談したい」は、佐々木花子、進路指導部の佐藤先生、管理者だけが閲覧できます。山田太郎、田中先生、鈴木先生、高橋健の一覧・詳細には表示されず、横断検索にも表示されません。

## 横断検索の期待結果

| 検索語 | 期待する種類 |
| --- | --- |
| 奨学金 | 奨学金説明会のお知らせ、公開Q&A、進路指導部の担当窓口 |
| 数学 | 数学小テストのお知らせ、数学カテゴリの公開Q&A、数学科の担当窓口 |
| ICT | ICT相談の公開Q&A、ICT担当窓口 |

質問検索はタイトル・本文・回答に加え、カテゴリ名と担当部署名を対象にします。`visibility='public'`の条件は維持され、private質問は検索されません。

## デモシナリオA：生徒

1. `demo.yamada@school.local`でログインします。
2. `/timeline`を開き、2年A組・2年・サッカー部向け連絡が表示されることを確認します。
3. 重要連絡の「確認しました」を操作します。
4. `/questions`で数学の公開質問を開き、田中先生の回答を確認します。
5. `/search`で「数学」を検索し、お知らせ・Q&A・担当窓口を確認します。

## デモシナリオB：教員

1. `demo.tanaka@school.local`でログインします。
2. `/school-posts/new`から2年A組向け連絡を投稿します。
3. 連絡詳細から確認状況画面を開き、対象人数・閲覧人数・確認人数と、確認済み・閲覧済み未確認・未読の氏名を確認します。この画面は連絡作成者と管理者だけが閲覧できます。
4. `/questions`で数学カテゴリの質問を開き、回答します。

## デモシナリオC：private相談

1. `demo.sasaki@school.local`でログインし、「進路・奨学金」を選んでprivate質問を投稿します。
2. ログアウトし、`demo.sato@school.local`でログインします。
3. 進路指導部へ届いたprivate質問が表示されることを確認し、回答します。
4. `demo.sasaki@school.local`へ戻り、回答を確認して解決済みにします。
5. `demo.yamada@school.local`または`demo.tanaka@school.local`でログインし、private質問が一覧・詳細・検索に表示されないことを確認します。

## デモシナリオD：管理者

1. `demo.admin@school.local`でログインします。
2. `/admin/users`でデモユーザー一覧を確認します。
3. ユーザー名、メールアドレス、初期パスワード、Roleを指定して新しいユーザーを追加します。
4. 一覧からRoleと有効状態を変更します。
5. `/admin/groups`で学年・クラス・部活動・委員会・部署を作成します。
6. 同じ画面の「ユーザーの所属設定」で所属とユーザーを選び、追加・解除を確認します。

## 既知の制約

- デモ用メールアドレスの`.local`は実メール送信には使えません。
- 初回ログイン時のパスワード変更強制機能は未実装です。デモパスワードを本番へ転用しないでください。
- 学校連絡の対象人数は、Roleや投稿者を除外せず、対象所属の全メンバーを集計します。
- seedはデモ用ユーザーの所属、対象連絡の既読状態、対象質問の回答を指定状態へ戻します。デモ操作後に再実行すると操作内容は初期状態へリセットされます。
